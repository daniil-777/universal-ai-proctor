# Critical engineering review

The app now has an independent codebase, conservative evidence tracking, and tested desktop/mobile workflows. The annotated answer benchmark still exposes model errors. Software correctness and model accuracy are assessed separately.

## Industry review, reports and saved accounts — 5 October 2026

| Finding | Implementation and boundary |
| --- | --- |
| Text logs did not provide a direct path to review a decision's video moment | Timed review events, milestones and operator bookmarks with explicit provenance; replay seeks only the matching uploaded video. Live sources retain available stills. Overview records are labeled separately. |
| A concern could disappear without an operator decision or handoff | A bounded exception desk with open/acknowledged/resolved states, mandatory resolution notes and decision history. Handoff and analysis reports retain unfinished work. Issue resolution never confirms workflow criteria. |
| Missing job preparation and context | Work-order/asset/operator fields plus suggested tools/principles checks, recorded as operator preparation. Source changes clear the active review; instruction changes reset preparation and label earlier evidence. No hidden safety condition is inferred from ticking a box. |
| Review images could bloat polling and sessions | Metadata-only refresh outside the evidence view, lazy thumbnails and explicit event/image/exception/history budgets. Retention omissions are included in exports. |
| Asynchronous bookmarking or reporting could attach replacement-source evidence | Source/reference/review guards before and after image preparation or rendering; report output also checks progress and goal revisions. Aborted requests cannot commit an operator bookmark. |
| Sharing depended on printing or an app session | On-demand local-font PDF and self-contained escaped HTML snapshots. Prepare a PDF before invoking the share menu from a fresh user gesture; unsupported file sharing falls back to download. No message is sent automatically. |
| Account registration could imply that the app was already online | Account UI states whether storage is local or hosted. No provider/public URL has been selected; registration stores data on the current server. Provider-neutral deployment instructions require HTTPS and persistent storage. |
| Saved results needed persistence and account isolation | Private SQLite records, ownership-scoped queries, expiring hashed tokens, asynchronous salted scrypt and matching-Origin account mutations. SQLite survives restart separately from transient live sessions. |
| Repeated saving or client-provided counts could inflate training metrics | Snapshots are built from guarded server state; one activity per account/source/reference is updated on resave. AI and manual completion counts remain separate. Visual-check counts exclude demo and earlier-reference observations; they are not certified proficiency or measured training duration. |
| Photographic evidence could be persisted without a deliberate storage choice | Account saves omit images by default and accept explicit photo opt-in. Original video/audio/document files are not copied, while names, workflow text, wishes and decisions remain part of the saved snapshot. |
| Private report generation could outlive logout or deletion | Ownership and authentication are rechecked after asynchronous PDF generation. Rendering and password hashing have bounded concurrency; account rate limits persist in SQLite. |
| Account authentication alone could be mistaken for hosted access control | Saved training is private, but anonymous AI/upload routes remain available. A hosted pilot needs an access gateway for the full app/API; the current deployment pattern is one instance on persistent disk. No email verification, password reset or enterprise role model is implemented. |
| Large PDFs could block the guidance loop despite an asynchronous route | Move font/PDF work into a worker scheduler with one active job, at most two queued snapshots and a 30-second deadline. Actual 3,000-criterion stress generated 1,533 pages while a main-thread timer fired after 61 ms; the synchronous baseline delayed it by 4,520 ms. Total process RSS still needs deployment headroom and measurement. |
| Canceling a download could leave expensive report work running | Thread abort signals through current and saved report routes. Remove queued canceled snapshots immediately, terminate active workers and release resources before admitting the next job; ownership is still rechecked before delivery. |
| Worker failures could expose raw document text or be mistaken for a valid PDF | Validate the PDF header/size and admit only allowlisted worker error codes. Report failures show retry/Offline HTML guidance without forwarding arbitrary worker messages. |
| PDF export could silently omit Chinese/Arabic characters absent from bundled fonts | Check the text that will actually be printed, reject unsupported glyphs with an actionable HTTP 422 error, and preserve all text in Offline HTML. Saved results expose the same HTML download option; metadata-only characters do not cause a false rejection. |
| Saved-report timeout or expired authentication could leave stale private content visible | Use a bounded 35-second download deadline with readable timeout/error feedback. A current 401 clears account history and the selected result; stale requests cannot overwrite newer account ownership. |
| Development proxy authentication could fail when Origin and Host were rewritten differently | Preserve the original Host through the Vite proxy and verify actual email/password/result/PDF flows on ports 8101 and 8180. Hosted configuration continues to pin the exact external origin rather than loosening account checks. |
| Readiness toggles could appear ignored until a network response arrived | Show the requested check state immediately with a per-context pending value; retain guarded server confirmation and recover on failure or source/reference changes. |
| A resave could miss manual confirmation/rewind changes with an unchanged review version | Rebuild the saved snapshot from current server state at that version, while rejecting older review versions and updating the same source/reference activity. |
| An intermittent browser camera acquisition failure lacked useful recovery | Explain denied, missing, busy and interrupted camera states and expose an explicit retry. The first expanded run had one acquisition failure, 20 focused repetitions passed, and the full 82-workflow run passed; this evidence does not prove hardware reliability or establish the original failure's cause. |
| Dependency cleanup could be reported as a completely clean development graph | Update vulnerable Vite/Vitest paths; both production graphs and the full backend audit report zero known findings. Seven high-severity findings remain in Tailwind 3 development transitive paths, including braces. No claim is made that those are resolved. |

The release has 381 passing unique checks (207 backend, 92 frontend and 82 browser workflows), plus six passing targeted repetitions after the final build. Production/development account smoke both verify the compiled worker and Unicode HTML fallback; extreme report stress and the earlier camera failure/repetition evidence are recorded in [VALIDATION.md](VALIDATION.md). This review describes implemented controls rather than a claim of industrial or clinical certification.

## Remaining accuracy limits

The fast model confuses some visible states in the prepared clips, omits facts, sometimes describes earlier content, and occasionally suggests reference actions for an unrelated scene. Conservative progress rules stop a single observation from completing steps, but repeated wrong model evidence can still be wrong. Inferred workflows can misinterpret the intended task (for example, flat shapes/bins as buttons). An annotated synthetic benchmark is useful for exposing these failures; it does not prove broad process comprehension.

The report compares complete model runs with the same current rubric. Raw replies, timestamps, exact expected answers and failed checks are reviewable. A low score is not automatically a software failure: omitted summary facts, uncertain interpretation and rubric wording are distinguished by inspecting the raw response. A high score on targeted regex rules is not comprehensive semantic correctness. Confidence remains model-reported and uncalibrated.

Camera, screen, media and speech tests use emulated viewports/fake devices where indicated. Physical iOS/Android hardware, browser permission pickers, actual speech transcription, noisy rooms and clinical procedure accuracy require their own recorded, expert-reviewed validation datasets. No claim of perfect surgical guidance is made.
